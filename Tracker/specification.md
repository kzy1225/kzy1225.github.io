# Habit Tracker Web App 要件定義・基本設計書

**文書番号：** HT-SPEC-001  
**バージョン：** 1.0  
**対象：** 個人利用・スマートフォン／PC  
**開発環境：** Google Apps Script + Google Sheets  
**タイムゾーン：** Asia/Tokyo  
**目標：** 習慣の実施・記録・振り返りを最小限の操作で継続可能にする

## 2.1 基本方針

1. 既存のHTの習慣を初期データとして取り込む。
2. 起床後、日中、帰宅後、就寝前など、タイミングを分けて入力できる。
3. 1項目変更するたびに保存し、途中で画面を閉じても記録を復元できる。
4. 毎日・隔日・N日ごと・週N回・イベント発生後などの異なる頻度に対応する。
5. Done / Not Due / Missed / Pendingを区別する。
6. Yes/Noだけでなく、日時、所要時間、数値、複数選択、自由記述に対応する。
7. 夜勤による日付またぎと、複数回の睡眠に対応する。
8. 習慣の追加・削除・頻度変更は、原則としてプログラム変更不要にする。
9. 達成率以外に、実施量・睡眠・勉強・掃除履歴なども分析する。
10. 原則無料で、長期的に一人で維持管理できることを重視する。

## 2.3 入力仕様

入力型は以下の7種類とする。

| 型 | 内容 | 使用例 |
|---|---|---|
| Boolean | 実施・未実施 | 水を飲む、歯磨き |
| Number | 数値 | 支出、実施回数、自己評価 |
| Duration | 所要時間 | 勉強、読書、運動 |
| DateTime | 日時 | 起床、就寝、帰宅 |
| Select | 単一選択 | 通常日、夜勤日、休息日 |
| MultiSelect | 複数選択 | 掃除箇所・内容 |
| Text | 自由記述 | 日記、振り返り |

Boolean型のHabitは状態の記録を中心とする。Duration型は実績値と目標値を別々に保存し、例えば「勉強120分」は目標240分に対して未達でも、実績120分を失わないようにする。

### 保存の動作

- ユーザーが項目を変更すると、その値を直ちにサーバーへ送信する。
- 保存要求中は「保存中」、確定後は「保存済み」を表示する。
- 保存エラー時は失敗状態を表示し、再送できるようにする。
- 同一の操作要求を再送しても二重記録されない設計にする。
- 入力変更は上書き可能とし、変更時刻も保持する。
- 同じ習慣を複数回実施できるものは、各実施記録を別々に保存する。
- 未保存のデータが存在する場合、保存済みと誤認させない。

## 2.4 Habit状態仕様

| 状態コード | 表示 | 定義 |
|---|---|---|
| DONE | Done | 対象となる行動を実施・目標達成 |
| NOT_DUE | 対象外 | 今回の評価対象ではない |
| MISSED | 未達成 | 対象だったが所定の期限までに未達成 |
| PENDING | 未入力 | 未判定、または実施期限前 |
| PARTIAL | 一部達成 | 数値目標の一部だけ実施（計算上の補助状態） |

PARTIALは実績値から導出し、基本の手動選択肢はDone / Not Due / Missedとする。未選択状態をPendingとして扱う。

**重要：** 入力途中のPendingを自動的にMissedへ変更しない。ユーザーが明示的に締め処理をするか、あらかじめ設定された評価期限と確定ルールを満たした場合に限る。

NOT_DUEについては理由を任意で記録できる。候補は「予定なし」「夜勤・休息」「体調」「予定変更」「その他」とする。

## 2.5 Due判定仕様

Due判定は、機械による提案とユーザーによる最終判定を組み合わせる。

| ルール | 定義 | 判定例 |
|---|---|---|
| EVERY_CYCLE | 生活サイクルごと | 起床後の水 |
| DAILY | 暦日ごと | 毎日実施する事務作業 |
| EVERY_N_DAYS | 前回実施からN日 | 洗濯、床モップ |
| WEEKLY_N | 週にN回達成 | 肩・背中、ランニング |
| EVENT | イベントを起点 | 起床後、帰宅後、就寝前 |
| MANUAL | 手動で対象を指定 | 買い物、臨時の掃除 |

週N回は日ごとにMissedを生成せず、週の終了時点で実施回数と目標回数を比較する。

EVERY_N_DAYSは最終実施日時を起点とする。暦日間隔と実時間（72時間など）は別ルールとして扱える構造にする。

Due判定結果には、機械が提案した状態とユーザーの最終決定をそれぞれ保存する。

## 2.6 夜勤・生活サイクル仕様

通常の暦日とは別に `LifeCycle` を定義する。

- 生活サイクルの開始は主睡眠からの起床時刻とする。
- 次の主睡眠後の起床時刻を次サイクルの開始とする。
- サイクルは日付をまたいでも同じIDで管理できる。
- 仮眠は主睡眠と区別し、サイクルを自動分割しない。
- 主睡眠か仮眠かは手動修正できる。
- 就寝前ルーティンは主睡眠開始を基準に判定する。
- 生活サイクルが確定していない間も入力を受け付け、確定後に紐付けを修正できる。
- 週次分析・家計分析には暦日基準を併用する。

具体例：

| 記録 | 日時 | 所属 |
|---|---|---|
| 起床 | 10月16日 14:00 | Cycle A開始 |
| 夜勤開始 | 10月16日 22:00 | Cycle A |
| 夜勤終了 | 10月17日 06:00 | Cycle A |
| 就寝 | 10月17日 08:00 | Cycle A |
| 起床 | 10月17日 16:00 | Cycle B開始 |

睡眠時間は睡眠区間の開始・終了差から算出する。主睡眠・仮眠の両方を記録でき、暦日別の集計では日付境界で睡眠時間を分割配賦する。

## 2.7 掃除・生活管理仕様

掃除は単なるチェック項目ではなく、独立した活動記録として扱う。

記録する情報：

- 実施日時
- 場所（机、床、キッチン、トイレ、風呂、洗面台、窓など）
- 作業種類（掃除機、モップ、拭き掃除など）
- 所要時間（任意）
- 備考（任意）

分析では、場所別の最終実施日、経過日数、実施頻度を表示する。

洗濯・買い物についても実施履歴を保持するが、掃除ほど詳細な入力は必須としない。

## 2.8 ダッシュボード仕様

### 日次・生活サイクル

- Due項目数
- Done / Missed / Not Due / Pending件数
- 判定済み対象の達成率
- 入力完了率
- 勉強時間・睡眠時間
- 実施予定の残り項目

### 週次

- 週N回習慣の充足率
- 習慣別の達成率
- 合計勉強時間
- 睡眠時間・就寝時刻の推移
- 支出合計
- 掃除履歴・未実施箇所
- 10段階自己評価
- 夜勤日・休息日・通常日ごとの比較

### 月次

- 習慣ごとの達成率推移
- 入力完了率
- 勉強時間合計と平均
- 睡眠時間分布
- 生活モード別の達成率
- 主な未達要因

基本達成率：

`DONE ÷ (DONE + MISSED) × 100`

ただし、数値習慣は目標充足率も別に計算する。週N回の未達は日次のMissed件数に重複加算しない。

Pendingが存在する場合には暫定集計と明示し、確定集計と区別する。小さなサンプルから因果関係を断定しない。

## 2.9 非機能要件

| 項目 | 要件 |
|---|---|
| 利用者 | 個人1人 |
| 対応端末 | iPhone、Windows PC |
| 画面 | スマートフォン優先のレスポンシブ設計 |
| 対応ブラウザ | Safari、Chrome、Firefoxの現行版を基本 |
| 言語 | 日本語 |
| タイムゾーン | Asia/Tokyo |
| 画面操作 | タッチで容易に選択できるUI |
| レスポンス | 通常操作で体感2秒程度を目標（保証値ではない） |
| データ保持 | 原則として全履歴を保持 |
| 可用性 | Googleサービスの稼働状況・利用制限に依存 |
| セキュリティ | 本人のみアクセス、秘密情報を画面コードに埋め込まない |
| バックアップ | 定期的なSheets/CSVの別ファイル保存 |
| 保守性 | 習慣設定をマスタデータとして分離 |
| 費用 | 無料枠内で運用 |
| オフライン | 初期版は必須としない。通信エラー時は未保存を明示 |

## 2.10 対象外

初期リリースでは次を対象外とする。

- 他ユーザーとの共有・ランキング
- Apple Healthなどの自動データ連携
- カレンダーからの自動予定取得
- AIによる自動生活改善提案
- バックグラウンドでの常時位置取得
- 完全オフライン対応
- 金融サービスとの自動接続

これらは本格運用の実績を確認した上で、必要性・費用・プライバシーを評価して追加する。
