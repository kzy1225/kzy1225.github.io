# ウェル活計算機 仕様書

- 作成・公式情報確認日：2026-10-20
- 設置ディレクトリ：`welkatsu/`
- GitHub Pages公開時のパス：`/welkatsu/`
- 対象：日本国内のWAON POINT対応のお客様感謝デー実施店舗
- 対応する買い物日：2026年4月20日〜2027年3月20日の毎月20日
- 非公式の買い物予算シミュレーター。実際のレジ決済額を保証するものではない。

## 1. 目的

現在保有するWAON POINTで購入できる税込金額を示す。複数の商品の税抜単価・税率・個数から税込合計を逐次計算し、使用ポイント、残ポイント、現金などで支払う必要がある額を表示する。各商品について、その商品だけを買う場合の最大個数も求める。

## 2. 公式ルールと根拠

### 2.1 お客様感謝デー

毎月20日、対象店舗でWAON POINTを200pt以上利用すると1.5倍分の買い物ができる。利用は整数ポイント単位。通常利用は1pt＝1円。入力するのはWAON POINT残高のみであり、Vポイントや電子マネーWAONポイントは合算しない。

感謝デーの1人1日あたりの上限：

| 店舗 | 2026年10月20日まで | 2026年11月20日から |
| --- | ---: | ---: |
| ウエルシアなど通常の対象店舗 | 30,000pt | 5,000pt |
| ウエルシアプラス | 30,000pt | 30,000pt |
| コクミン | 30,000pt | 10,000pt |
| MASAYA / COLOR STUDIO / NARCIS | 10,000pt（2026年4月20日から） | 10,000pt |

上限の情報が異なる場合は、旧FAQよりも新しい2026年10月1日掲載の公式変更告知を優先する。複数店舗・複数会計でも使い放題ではないため、当日使用済みポイントを別途入力する。店舗をまたぐ上限適用の詳細は自動推測せず、選択店舗の上限と入力した使用済みptで保守的に試算する。

処方せん調剤、POSAカード、たばこ、公共料金などはポイント支払い対象外。商品一覧には含めず、別会計として確定した税込支払額を加算する。ポイント利用分のポイント付与は計算しない。一部対象外店舗、Vポイントのみ対応の例外店舗、ネットショップは対象外。

### 2.2 消費税

確認日時点の標準税率10％、軽減税率8％を使用する。

- 8％：対象の飲食料品など。酒類・外食を除く。
- 10％：日用品・酒類など。
- 商品の税率は利用者が選択する。名称からの自動判定は行わない。
- 一つの会計の税抜金額を税率ごとに合算し、税率ごとに1回だけ税額の端数処理を行う。
- 端数処理は切り捨て、四捨五入、切り上げから選択。国税庁は切り捨てだけを義務付けていない。
- 初期設定の切り捨ては本ツールの試算設定であり、ウエルシアのPOS処理を公式に確認したものではない。
- 表示税額はポイント充当前の参考額。レシート上の値引き配賦・課税標準の再計算を再現しない。税務申告・適格請求書の作成には利用しない。
- 2027年4月以降の税制はこの版の適用範囲外。現行税率を無期限に適用しないよう日付入力に上限を設ける。

## 3. 入力項目

| 項目 | 初期値・範囲 | 意味 |
| --- | --- | --- |
| 現在保有pt | 0、0〜10,000,000の整数 | 当日過去の会計後の現在残高 |
| 買い物日 | 日本時間の直近の20日。当日が20日なら当日 | ルールの適用日。範囲内の20日のみ |
| 店舗 | 通常店舗 | 上限区分を選択 |
| 当日使用済みpt | 0、0〜10,000,000の整数 | 上限残枠算出用。現在残高から再度引かない |
| 商品名 | 空、最大60文字 | 任意のメモ |
| 税抜単価 | 空、入力時は1〜1,000,000円の整数 | 値引き後の単価。小数円は非対応 |
| 税率 | 8％ | 8％・10％ |
| 個数 | 1、0〜100,000の整数 | 0個は計上しない |
| 必要ptの端数 | 切り上げ | 切り上げ／切り捨て |
| 消費税の端数 | 切り捨て | 切り捨て／四捨五入／切り上げ |
| 別会計の対象外支払額 | 0、0〜10,000,000円の整数 | 税込確定額。二重課税・ポイント充当しない |

商品行は1〜100行。追加・削除が可能。最後の行を削除した場合は空行を1行残す。

空の税抜価格行は計算対象から外し、その行数を表示する。負数、小数、範囲外、不正な日付・選択値はエラーを表示し、全体結果を「—」にして誤解を防ぐ。自動で不正値を0円として確定しない。税込合計が大きくなる場合も、設定した入力上限内ではJavaScriptの安全な整数範囲に収まる。

## 4. 計算式

### 4.1 利用できるポイント

```text
B = 現在保有ポイント
L = 買い物日・店舗から求めた1日上限
U = 当日すでに使ったポイント
A = min(B, max(0, L - U))

購入可能金額の上限目安 =
  A >= 200 のとき floor(A × 3 / 2)
  A <  200 のとき A
```

1.5倍の金額は対象商品の税込合計が300円以上で使える上限目安。価格や最低条件によって使い切れないことがある。

### 4.2 商品総額

```text
S8  = 8％商品の Σ(税抜単価 × 個数)
S10 = 10％商品の Σ(税抜単価 × 個数)
T8  = 端数処理(S8 × 8 / 100)
T10 = 端数処理(S10 × 10 / 100)
G = S8 + S10 + T8 + T10
```

税率別の税額を求めてから合計する。商品ごとに丸めた税込金額を積み上げない。浮動小数の誤差を避けるため税額は整数の分子から計算する。商品行には税抜小計を表示する。

### 4.3 ポイントと現金等の支払い

**以下の端数処理はシミュレーション上の仮定。公式のPOS仕様として断定しない。**

`A >= 200` かつ `G >= 300` の場合：

```text
現金を最小にする：R = ceil(G × 2 / 3)
端数を現金で払う：R = floor(G × 2 / 3)
P = min(A, R)
V = floor(P × 3 / 2)
充当額 C = min(G, V)
```

最低条件を満たさない場合は、通常利用として `P = min(A, G)`、`C = P`。

```text
X = 別会計のポイント対象外の支払額（税込）
現金などの支払額 = G - C + X
会計後の残ポイント = B - P
通常のポイント利用に比べたお得額 = C - P
```

余剰のポイント相当額を現金のお釣りとして扱わない。残ポイントには当日の上限により使えなかったptも残る。上限超過部分への追加の1倍ポイント充当はモデルに含めず、現金などの不足額として表示する。

### 4.4 最大購入個数

商品ごとに、他の商品を含めず、当該商品だけを購入する場合を計算する。

1. 利用可能ptから税込予算を求める。
2. `税抜価格 × n + 端数処理(税抜価格 × n × 税率 / 100)` が予算以下になる最大の整数 `n` を二分探索する。
3. 得られた購入額が300円未満なら1.5倍は適用できないため、1pt＝1円の予算で再計算する。
4. 必要pt切り上げモードで現金0円となる個数を表示する。画面の切り捨てモード選択とは独立。

各行の最大個数を同時に購入できることを意味しない。別会計の対象外支払額は最大個数に含めない。組み合わせの自動最適化・残り予算で追加できる数は対象外。

## 5. 画面・動作

- 日本語、スマートフォン対応。ウエルシアをイメージした青と黄色を使い、白のカードで入力と結果を区別する。公式サイト・公式ツールを装うものではない。
- 01：ポイント・買い物日・店舗・当日使用済みpt・購入可能額。
- 02：商品リスト。追加、削除、入力例（既存入力上書き前に確認）。
- 03：端数設定と対象外の別会計額。
- 結果：個数合計、税抜合計、税率別税額、税込合計、使用pt、充当額、残pt、対象外額、現金等支払額。
- 入力・選択変更のたびに自動更新。計算ボタンは不要。
- 広い画面では結果を右側に固定表示。モバイルは1列で表示し、画面下部に現金等支払額と内訳へのリンクを固定表示。
- 結果は`aria-live="polite"`、入力にラベル、フォーカス表示、エラー表示を用意。
- 公式資料と前提をページ内に掲載。非公式であること、確認日を明記。
- JS無効時は計算できない旨を表示。
- ホームのツール一覧に本ページへのリンクを追加。

## 6. 保存とプライバシー

`localStorage`の`kzy1225.welkatsu.v1`に入力を自動保存。同じブラウザーで再訪した場合に復元する。保存した買い物日が日本時間の今日より前なら、次の20日に進め、当日使用済みptを0に戻す。保有残高は自動取得・自動更新しない。

リセットは確認後にフォームと保存内容を初期値に置き換える。他ツールの保存情報は削除しない。保存不可・破損時も計算を続けられる。商品の文字列をHTMLとして挿入しない。

入力内容をサーバーに送信しない。Google Fontsのみ外部通信が発生し、フォント取得不可の場合は端末のフォントへフォールバックする。アカウント連携・分析・広告はない。

## 8. 受入条件・テスト例

| 条件 | 期待値 |
| --- | --- |
| 200pt、対象商品税込300円 | 200pt使用、現金0円 |
| 199pt、対象商品税込300円 | 1倍、199pt使用、現金101円 |
| 200pt、対象商品税込299円 | 1倍、200pt使用、現金99円 |
| 1,000pt、食品198円×3、日用品398円×2 | 税抜1,390円、税126円、税込1,516円、現金16円 |
| 税込301円、十分なpt、必要pt切り上げ | 201pt、現金0円 |
| 同条件、必要pt切り捨て | 200pt、現金1円 |
| 1,000pt、税抜198円・8％の商品だけ | 最大7個 |
| 200pt、税抜250円・8％の商品だけ | 最大0個（1個270円では最低条件を満たさない） |
| 通常店舗、11月20日、保有10,000pt・使用済4,500pt | 今回利用可能500pt、上限目安750円 |
| 食品税抜99円×3個、税切り捨て | 税23円、税込320円（個別の丸めをしない） |
| 対象外税込500円を追加 | 商品合計・ポイントは変わらず、現金等支払額が500円増える |
| 不正入力 | 結果を「—」にし、原因を表示 |

自動テストは上限の切替・例外店舗・最低条件・端数処理・混在税率・最大個数を検証する。広い入力組み合わせで最大個数の境界と支払額の保存則も確認する。

## 9. 今後の改定

キャンペーン条件・税率が変わった場合、一次資料を再確認し、`calc.mjs`のルール、日付の許容範囲、画面の説明、仕様書、境界テストを一緒に更新する。公式情報を自動取得する機能はなく、「確認日以降も常に最新」とは表示しない。
